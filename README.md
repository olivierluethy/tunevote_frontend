The **web client** for TuneVote, a real-time collaborative music-listening app. People join a shared listening room ("session"), suggest YouTube songs, and vote in rounds to decide what plays next — with everyone's audio kept in sync across devices.

This repository is the **user-facing single-page app (PWA)**. It renders the whole experience and talks to the companion backend, [`tunevote_api`](https://github.com/olivierluethy/tunevote_api), over REST + WebSockets. The rules for playback, voting, and persistence all live in the API — this repo is the interface to them.

## What it does

- **Auth** — email/password login & registration, password reset, and Google/Facebook OAuth. Registered users carry a JWT; anonymous visitors can join a session as a **guest** with just a nickname (guest token).
- **Sessions dashboard** — create public or private sessions, see which rooms are live "on air", join with one tap, and manage invitations (send, accept, reject, revoke) with QR-code sharing.
- **The session room** — a state-machine-driven UI that moves through *suggesting → voting → playing* phases. Users search YouTube (or paste a link), propose songs, and vote; the host controls when the session starts.
- **Synchronized playback** — a single persistent YouTube player, mounted once at the app root, keeps playing as you navigate. It uses NTP-style clock-offset correction so every device plays the same position, with drift correction, autoplay-retry, and lock-screen media controls.
- **Persistent mini-player** — a radio-style now-playing bar (and full queue overlay) so you can vote and suggest without leaving the page you're on.
- **AI suggestions** — request AI-picked songs to keep a room from going quiet (generated by the API).
- **Profiles & stats** — listening summaries, top songs/artists, and charts; public user and artist pages, plus a threaded "shouts" wall on artist pages.

## Tech stack

- **React 19** + **Vite 7** (plain JSX, ES modules)
- **Tailwind CSS 3** — dark, glassmorphic, gradient-heavy theme (`darkMode: "class"`, Inter font)
- **React Router 7** for routing
- **Socket.IO client** for real-time playback sync, live participant counts, and voting-phase updates
- **Axios** for REST calls
- **Framer Motion** for animation
- **YouTube IFrame Player API** as the audio engine + **YouTube Data API v3** for song search
- **Chart.js** (profile statistics), **qrcode.react** (share links)
- Installable **PWA** via `vite-plugin-pwa`
- **Google Analytics (gtag)** wrapper for product analytics

## Key routes

| Path | Purpose |
|---|---|
| `/login`, `/register`, `/forgot-password`, `/reset-password/:token` | Authentication |
| `/dashboard` | Main hub — create/browse/join sessions, manage invites |
| `/session/:sessionId` | The core listening room (voting + playback) |
| `/profile`, `/user/:userId` | Own profile with stats / public user profile |
| `/artist/:artistId` | Artist page + shouts wall |
| `/invite/:token` | Invite redirect into a private session |
| `/auth/google/callback`, `/auth/facebook/callback` | OAuth landing |

## Getting started

**Prerequisites:** Node.js 18+ and a running instance of the [`tunevote_api`](https://github.com/olivierluethy/tunevote_api) backend.

```bash
npm install
npm run dev      # start the Vite dev server with HMR
```

Then open the printed local URL (default http://localhost:5173).

### Environment variables

Create a `.env` file in the project root. All client-facing vars must be `VITE_`-prefixed:

```env
VITE_API_URL=http://localhost:4000/           # base URL of the tunevote_api backend
VITE_YOUTUBE_KEY=your_youtube_data_api_v3_key # for song search
VITE_GA_MEASUREMENT_ID=G-XXXXXXXXXX           # Google Analytics measurement ID (optional)
```

> ⚠️ **The backend URL is not fully env-driven yet.** `VITE_API_URL` is only wired into some pages (Profile, ArtistDetail, UserDetail). Several core files (`Dashboard.jsx`, `SessionPage.jsx`, `PlaybackContext.jsx`, `Login.jsx`, `InviteRedirect.jsx`) currently **hardcode** `https://api.tunevote.com/`. To point the app at a different backend you must change both the env var and those literals. Consolidating them into a single API-client module is a known cleanup.
>
> ⚠️ **Secrets are bundled into the client.** Because these vars are `VITE_`-prefixed they ship in the built JS. Don't commit real keys; restrict the YouTube key by HTTP referrer and treat anything here as public.

## Project layout

```
src/
  main.jsx                 # real app entry — router + providers
  pages/                   # Login, Register, Dashboard, Profile, ArtistDetail, UserDetail, ...
  components/
    SessionPage.jsx        # the core session room
    MiniPlayer.jsx         # persistent now-playing bar
    QueueOverlay.jsx       # vote/suggest overlay
    session/               # SessionHeader, NowPlayingCard, VotingBanner, SearchPanel, modals, ...
  context/
    PlaybackContext.jsx    # single global YouTube player + Socket.IO playback sync
  utils/
    auth.js                # JWT vs guest-token handling
    analytics.js           # Google Analytics wrapper
```

> Note: `src/App.jsx` is leftover Vite scaffolding and is unused — the real entry point is `src/main.jsx`.
